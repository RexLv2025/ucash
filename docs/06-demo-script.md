# UCash 演示走查脚本（8 分钟）

> 目标：用最短路径证明「功能完备，不是界面演示」——每步都落库、都有状态流转、都能在后台看到轨迹。

## 0. 准备（1 分钟）

```bash
npm --prefix apps/server run seed -- --reset   # 重置为演示数据
npm run dev:server                              # :4000
npm run dev:admin                               # :5173
cd apps/mobile_flutter && flutter run           # 安装到手机/模拟器
```

- App 端「设置 → 开发者选项」确认服务端地址（真机填电脑局域网 IP）
- 后台打开 `http://localhost:5173`，用 `admin / Admin@123` 登录

## 3. 异常态验证（1 分钟）

| 场景 | 复现方式 | 预期 |
|---|---|---|
| 放款失败 E1024 | 绑定卡号尾号 `0000` 的卡并借款 | 失败页显示错误码、原因、换卡重试按钮；后台订单为「放款失败」 |
| 额度不足 | 借款金额超过可用额度 | 滑块上限被限制，试算接口返回 4002 |
| 合同未签 | 不勾选合同直接提交 | 前端拦截 + 后端 5003 双重保护 |
| 重复下单 | 连续快速点击确认借款 | 第二次返回 5004「处理中」，不产生重复借据 |
| 学生拦截 | 职业选「学生」提交实名 | 拒绝，提示不支持向在校学生提供服务 |
| 越权访问 | 用 A 的 token 请求 B 的借据 ID | 返回 1004，不泄露数据 |

## 4. 一句话结论素材

- 借款下单走的是服务端签名 `quoteToken`，客户端改金额会直接验签失败
- 每笔借款都有 `risk_decisions` 快照，规则变更可回溯到具体决策
- 还款后额度实时释放，`Σ期供本金 = 借据本金` 恒等，账务无浮点误差
- 全量敏感字段 AES-256 加密、展示脱敏、高危操作写审计
