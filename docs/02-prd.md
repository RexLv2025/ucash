## 0. 阅读指引

1. **第 1~2 章**面向业务方与合规：定位、指标、角色边界。
2. **第 3 章**面向研发排期与测试设计：78 项功能清单，每项带可测量验收标准。

4. **第 6 章**面向后端与算法：所有金额、利率、罚息、券的计算口径，前端**不得**自行计算。

> **口径红线**：文档中出现的所有金额、利率、月供数值（如 ¥726.40、16.6%）均为**视觉示意值**，真实数值一律由服务端 `POST /api/loan/quote`、`GET /api/credit/result` 返回。客户端仅做格式化展示，禁止本地复算，避免四舍五入口径分裂（详见 6.1、6.2）。

## 1. 产品定位与目标

### 1.1 背景与机会

- **业务问题**：持牌小贷/助贷机构的线下获客成本高、单客审批链路长（平均 2~3 天），长尾用户（月收入 5,000~15,000 元、无信用卡或额度不足）在 1,000~50,000 元、3~12 期的短中期资金需求上缺少"分钟级到账"的合规产品。
- **机会**：移动端全流程线上化后，可将"注册→授信→首借→到账"压缩至 10 分钟内，用数据化风控替代人工尽调，单客获客成本可下降 40% 以上。
- **依据**：本项目已完成需求确认，目标用户、核心场景、端组合与预算约束见 `01-requirement.md`；端选型结论（RN + Expo 客户端 / Vite + React 后台）见 `03-platform.md`，本文档不重复论证、不私自变更。
- **对标对象**：360 借条（功能完备度参照），差异点在于**授信进度可视化**与**放款失败的确定性补救路径**（本项目 7 张设计稿中的"激活额度""放款失败"两页即差异化落点）。

### 1.2 产品定位

> **一句话定位**：给有稳定收入的工薪人群，提供 500~50,000 元、3/6/12 期、最快 3 分钟到账的合规线上小额现金贷。

| 维度 | 定义 |
|------|------|
| 目标用户 | 22~45 周岁、月收入 5,000~15,000 元、有稳定社保/公积金或代发工资流水、征信无严重不良的工薪族与个体经营者 |
| 核心场景 | ① 临时周转（医疗、房租、学费）② 消费补差（大额耐用品）③ 信用卡还款缺口 |
| 价值主张 | 额度看得见（预估额度前置）、进度看得懂（认证 1/3 可视化）、失败有出路（放款失败给 3 条补救路径） |
| 资金方 | 持牌小贷公司 / 银行助贷，App 内所有利率与费用披露以资金方口径为准 |
| 明确不做 | 学生贷、首付贷、炒股/购房用途、无场景大额信贷（>20 万）、跨境资金 |

### 1.3 业务目标与北极星指标

| 类型 | 指标 | 目标值（首月 / M3） | 统计口径 | 数据来源 |
|------|------|--------------------|----------|----------|
| **北极星指标** | 周放款成功单量 WDL（Weekly Disbursed Loans） | 首月 ≥ 300 单/周；M3 ≥ 1,250 单/周 | 自然周（周一 00:00~周日 23:59）内 `loan.status = DISBURSED` 的借款单数，剔除去重后的同一用户多笔 | 借款单表 + 放款流水表 |
| 业务目标 1 | 首月放款成功单量 | ≥ 1,200 笔 | 注册后 30 个自然日内成功放款笔数 | 同上 |
| 业务目标 2 | M3 单月放款金额 | ≥ 2,500 万元 | 放款成功金额合计（不含失败重试） | 放款流水表 |
| 业务目标 3 | 注册→首借转化率 | ≥ 8%（M3 ≥ 12%） | 见 1.4 漏斗定义 | 埋点 + 借款单表 |
| 业务目标 4 | 首借→复借转化率（60 天内） | ≥ 25%（M3 ≥ 40%） | 首借结清或正常还款 ≥1 期后 60 天内产生第 2 笔借款的用户占比 | 借款单表 |
| 业务目标 5 | 首逾率 DPD1 | ≤ 8%（M3 ≤ 6%） | 首期应还日次日仍未还清的首借订单占比 | 账单表 |
| 业务目标 6 | 放款失败自助挽回率 | ≥ 60% | 放款失败后 24h 内通过换卡/重试成功的订单占比 | 放款工单表 |

### 1.4 核心转化漏斗

漏斗定义（同一自然月内，按用户去重，逐级严格包含）：

| 层级 | 环节 | 定义（事件口径） | 行业基准 | 本项目目标 | 主要流失原因 | 对应优化功能 |
|------|------|-----------------|---------|-----------|-------------|-------------|
| L1 | 注册 | `auth_register_success`（手机号首次验证通过） | — | 基准 100% | — | F-ACC-01 |
| L2 | 实名 | `kyc_realname_success` | 70%~85% | ≥ 80% | 三要素不匹配、放弃填写 | F-KYC-01、认证进度可视化 |
| L3 | 授信提交 | `credit_apply_submit` | 80%~90% | ≥ 85% | 人脸失败、联系人授权抗拒 | F-KYC-02/03、F-CRD-02 |
| L4 | 授信通过 | `credit_approve`（风控决策=通过） | 25%~40% | ≥ 35% | 多头借贷、征信不良、额度不足预期 | F-CRD-03/05 |
| L5 | 首借下单 | `loan_order_success`（合同签署完成） | 30%~50% | ≥ 40% | 费率犹豫、到账卡缺失、合同犹豫 | F-LN-03/04/07 |
| L6 | 放款成功 | `disburse_success` | 85%~95% | ≥ 92% | 银行卡状态异常、银行通道超时 | F-DSB-03/04 |
| L7 | 复借 | `loan_order_success`（第 2 笔） | 20%~40% | ≥ 25% | 额度未恢复、体验断点 | F-CRD-06、F-GRW-01 |

**端到端**：L1→L6 目标 ≥ 8%（0.80 × 0.85 × 0.35 × 0.40 × 0.92 ≈ 8.8%）。

**漏斗断点监控规则**：任一层级周环比下降 > 15% 且绝对值低于基准，触发运营告警，48h 内出归因报告。

### 1.5 成功度量与验收口径

| 度量项 | 目标 | 验收方式 |
|--------|------|----------|
| 核心闭环可用 | 首借全流程（注册→到账）端到端成功率 ≥ 95%（剔除用户主动放弃） | 灰度 200 单实测 |
| 页面性能 | 首页首屏 < 1.5s（4G）、试算响应 < 400ms（P95） | 埋点 `perf_*` |
| 崩溃率 | 崩溃用户占比 < 0.5% | 客户端监控 |
| 合规项 | 利率披露、协议勾选、隐私授权、注销入口 4 项 100% 覆盖 | 合规 checklist 逐项签核 |
| 数据完整性 | P0 埋点事件到达率 ≥ 99% | 埋点校验脚本 |

### 1.7 合规基线（P0 强制项）

| 编号 | 合规要求 | 产品落点 | 验收标准 |
|------|----------|----------|----------|
| C-01 | 利率明示 | 确认借款页、合同、首页展示"综合年化利率 X%（单利）" | 全 App 无"日息低至""零利息"等误导表述；任一借款页均可见年化 |
| C-02 | 综合成本上限 | 利息+服务费+罚息合计年化 ≤ 24% | 定价引擎强制校验，超限拒绝出单 |
| C-03 | 知情同意 | 登录页、认证页、合同页均有独立勾选框，默认不勾选 | 未勾选时主按钮置灰，点击给 toast |
| C-04 | 个人信息最小化 | 仅采集风控必需字段，授权书列明用途与保存期限 | 隐私政策逐项对应采集字段 |
| C-05 | 注销权 | "我的→设置→注销账号"两级可达 | 注销入口 ≤ 2 次点击；注销后 15 日内删除 |
| C-06 | 冷静期 | 授信拒绝后 30 天内不可重复申请 | 重复申请返回 `CREDIT_COOLDOWN` 并展示剩余天数 |
| C-07 | 征信授权 | 授信前单独签署《征信查询授权书》 | 未签署不得调用征信接口，日志留痕 |
| C-08 | 催收合规 | 仅联系本人及授权紧急联系人，每日 ≤ 3 次，21:00~08:00 不打扰 | 催收台账记录时间与对象，超限拦截 |

### 2.3 数据权限与审计规则

1. **字段脱敏**：后台列表页手机号显示 `138****6688`、身份证 `3101**********1234`、银行卡 `**** **** **** 6688`；查看明文需"申请-超管审批-记录日志"三步，单次授权 30 分钟。
2. **数据范围**：审批员仅可见分配给自己的工单；风控员可见风险决策明细但不可见完整合同文本。
3. **高危操作清单**（强制二次确认 + 短信验证码 + 审计日志）：调额、调价、罚息减免、批量导出、规则发布、角色变更、代客还款。
4. **审计日志字段**：`operator_id`、`operator_role`、`action`、`target_type`、`target_id`、`before_value`、`after_value`、`ip`、`ua`、`created_at`、`trace_id`；日志不可删除、保留 ≥ 5 年。
5. **会话安全**：后台会话 30 分钟无操作自动登出；连续 5 次密码错误锁定 30 分钟。

```
老用户 → 打开 App → 首页（已授信态）
      → 展示"可用额度 ¥42,000 / 已用 ¥8,000"
      → 点击"立即借款" → 确认借款 P-11
      → [额度是否有效]
          ├─ 有效（30 天内且未冻结）→ 直接试算 → 选券/选卡 → 合同签署（复用已签主体协议，仅签本笔借款合同）
          └─ 过期/冻结 → 重新授信（复用已认证资料，仅需补充授权确认）→ 回到 P-11
      → 提交订单 → 放款
```

**与首借的差异点**

| 环节 | 首借 | 复借 |
|------|------|------|
| 认证 | 三要素+人脸+联系人全量 | 资料复用，< 90 天免重复人脸；> 90 天需再次活体 |
| 授信 | 完整决策 | 增量决策（仅查额度是否可提、是否触发重新评估） |
| 合同 | 借款合同 + 服务协议 + 征信授权 | 仅签本笔借款合同（主体协议已在有效期内） |
| 到账卡 | 需新增 | 默认上次成功卡 |
| 前置校验 | 无 | 校验是否存在进行中订单（有则拦截 `LOAN_IN_PROGRESS`） |

**异常分支**：额度已用满 → 引导"提前结清恢复额度"；存在逾期 → 拦截并跳账单页；额度冻结 → 展示冻结原因与解冻条件。

### 4.3 提前结清流程

```
账单页 P-19 → 点击"提前结清" → 提前结清页 P-21
  → GET /settle/quote?loanNo=X
  → 展示"剩余应还本金 / 当期利息 / 违约金 ¥0 / 合计应还 / 可省利息"
  → 用户点击"确认结清"
  → [10 分钟内] → 收银台 P-22 → 支付
      ├─ 成功 → POST /settle/confirm → 状态 SETTLED
      │        → 还款结果页 P-23（结清证明 + 额度已恢复）
      │        → 返回账单页，剩余期次全部"已结清"
      └─ 失败 → 结果页展示失败原因 + "重新支付"（settleId 不变）
  → [超 10 分钟] → 返回 `SETTLE_QUOTE_EXPIRED`，自动重算并提示"金额已更新，请确认"
```

**关键规则**
1. 结清金额 = 剩余未偿本金 + 截至结清日应计利息（按日）+ 违约金（0）− 未到期利息冲减；**永远 ≤ 按期还完的总额**。
2. 已逾期订单结清时，先冲罚息再冲本息，结清后 DPD 归零，但历史逾期记录不消除。
3. 结清成功后额度恢复 = 该笔借款占用额度，恢复延迟 ≤ 2s。
4. 存在"支付中"的还款单时，禁止发起结清（`REPAY_IN_PROGRESS`）。

**异常分支**：支付超时 → 订单保持 `PAYING`，10 分钟后自动查单，成功则结清、失败则回滚为待还；重复支付 → 幂等返回首次结果，多扣款项 T+1 原路退回。

### 4.4 放款失败补救流程

```
放款失败 P-16（失败码 E1024 银行卡状态异常）
  ├─ 路径 A：更换收款银行卡（推荐）
  │    → P-26 新增/选择卡 → 四要素校验 → 绑定成功
  │    → 自动调 POST /disburse/retry {loanNo, cardId}
  │    → [成功] → P-15 三步全绿 → 推送"已到账"
  │    → [再次失败] → 回 P-16，失败码更新；换卡 ≥3 次转人工
  ├─ 路径 B：稍后重新申请
  │    → 生成重试任务（30 分钟后执行，最多 2 次）
  │    → 用户回首页，订单保持 DISBURSE_FAILED
  │    → 重试成功 ⇢ 推送；两次均失败 → 转人工工单
  └─ 路径 C：联系在线客服
       → 在线客服（9:00~21:00）/ 热线 400-000-0000
       → 客服可在后台发起"通道切换重试"
```

**失败码与补救映射**（完整表见 8.3）

| 失败码 | 含义 | 自助可解决 | 推荐路径 |
|--------|------|-----------|---------|
| E1024 | 银行卡状态异常（注销/冻结/超限） | 是 | A 换卡 |
| E1001 | 银行系统繁忙/超时 | 是 | B 稍后重试 |
| E1002 | 收款账户信息不符（姓名/证件不一致） | 是 | A 换卡 |
| E1025 | 风控二次拦截 | 否 | C 客服 |
| E1026 | 放款通道额度不足 | 否 | B 稍后（>2h） |
| E1099 | 未知异常 | 部分 | B → C |

**兜底原则**：失败订单不生成账单、不产生任何费用、不占用额度超过 24h（超时自动释放并关闭订单）。

### 4.5 主动还款流程（含逾期）

```
账单页 P-19 → "立即还款"
  → [是否逾期]
      ├─ 否 → 收银台 P-22（应还 = 当期本息）
      └─ 是 → 收银台 P-22（应还 = 当期本息 + 罚息，红色单列罚息）
  → 选择支付方式 → 确认支付
  → POST /repay/create {loanNo, period, amount}  → 返回 repayNo
  → 拉起支付（模拟）
  → [支付成功] → POST /repay/notify 回调
       → 冲抵：罚息 → 利息 → 本金
       → 账单状态"已还"，APP 3s 内刷新
       → 还款结果页 P-23（金额/时间/流水号/电子回单）
       → 若为末期 → 借款单置 SETTLED，额度恢复
  → [支付失败] → 结果页失败态 + "重新支付"（repayNo 不变）
  → [支付超时] → 订单保持 PAYING，10 分钟后查单补偿
```

**异常分支**：重复支付 → 幂等；支付成功但回调丢失 → 前端轮询 `GET /repay/{no}` 最多 5 次（间隔 2s），仍未知则提示"支付结果确认中，请勿重复支付"；余额不足 → 提示更换支付方式。

### 4.6 授信拒绝与冷静期流程

```
授信决策 REJECT → P-10 拒绝页
  → 展示：图标 + "本次暂未通过审核"
  → 拒绝原因（分类文案，不暴露规则）：如"当前负债水平较高"
  → 建议动作：如"结清其他平台借款后 30 天再试"
  → 冷静期倒计时："可在 2026-12-08 后再次申请"
  → 操作：[返回首页] [联系客服]
  → 30 天后：首页恢复"立即借款"，申请时重新走完整决策
```

**规则**：冷静期内申请接口返回 `CREDIT_COOLDOWN` + `remainDays`，**不消耗征信查询次数**；同一自然年拒绝 ≥3 次进入灰名单，需人工复核才可再申请。

### 4.7 注销流程

```
我的 P-25 → 设置 P-31 → 注销账号 P-32
  → 校验：无未结清借款 / 无进行中订单 / 无在途还款
      ├─ 不通过 → 列出待处理项（订单号 + 金额 + 入口链接），阻断注销
      └─ 通过 → 展示注销影响清单（合同保留、征信记录不删除、积分券作废）
  → 勾选"我已了解" → 获取验证码 → 提交
  → 状态置 CANCELLED_PENDING，进入 15 天冷静期
  → 冷静期内登录 → 弹窗"账号注销中，是否撤销？" → [撤销] 恢复 ACTIVE
  → 15 天后 → 置 CANCELLED，清除可识别信息，手机号可重新注册
```

## 6. 业务规则与算法口径

> **总原则**：所有金额与利率计算**只在服务端**进行，客户端只做格式化展示。同一业务对象（quote、settle、repay）在全链路必须**同一口径、同一精度、同一舍入规则**，避免"页面 719.80、账单 719.79"这类分裂。

### 6.1 等额本息（核心算法）

#### 6.1.1 符号与公式

| 符号 | 含义 | 单位 |
|------|------|------|
| `P` | 借款本金 | 元（分精度） |
| `i` | 月利率 = 综合年化（单利）/ 12 | 小数，保留 8 位 |
| `n` | 期数（3/6/12） | 期 |
| `A` | 每期应还（月供） | 元 |

**月供公式**

```
        P × i × (1 + i)^n
A = ─────────────────────────
          (1 + i)^n − 1
```

**逐期计算（摊销法）**

```
第 k 期：
  利息_k   = ROUND_HALF_UP( 剩余本金_{k-1} × i , 2 )
  本金_k   = ROUND_HALF_UP( A − 利息_k , 2 )
  剩余本金_k = 剩余本金_{k-1} − 本金_k
  应还_k   = 本金_k + 利息_k        （k = 1..n−1）
```

**末期平账（强制）**

```
第 n 期：
  本金_n = 剩余本金_{n-1}                  ← 不再用 A − 利息_n
  利息_n = ROUND_HALF_UP( 本金_n × i , 2 )
  应还_n = 本金_n + 利息_n
```

**平账校验（服务端出单前必须通过，否则拒绝出单）**

| 校验项 | 条件 |
|--------|------|
| 本金闭合 | `|Σ本金_k − P| ≤ 0.01` |
| 利息闭合 | `|Σ利息_k − 总利息| ≤ 0.01` |
| 末期偏差 | `|应还_n − A| ≤ 1.00` |
| 单调性 | 每期利息单调递减、本金单调递增 |

#### 6.1.2 完整示例（本金 8,000 元 / 12 期 / 月利率 1.2% / 综合年化 14.4% 单利）

`A = 8000 × 0.012 × 1.012^12 / (1.012^12 − 1) = 719.80 元`

| 期次 | 期初剩余本金 | 利息 | 本金 | 应还 | 期末剩余本金 |
|------|-------------|------|------|------|-------------|
| 1 | 8,000.00 | 96.00 | 623.80 | 719.80 | 7,376.20 |
| 2 | 7,376.20 | 88.51 | 631.29 | 719.80 | 6,744.91 |
| 3 | 6,744.91 | 80.94 | 638.86 | 719.80 | 6,106.05 |
| 4 | 6,106.05 | 73.27 | 646.53 | 719.80 | 5,459.52 |
| 5 | 5,459.52 | 65.51 | 654.29 | 719.80 | 4,805.23 |
| 6 | 4,805.23 | 57.66 | 662.14 | 719.80 | 4,143.09 |

> 末期应还 719.84 与标准月供 719.80 差 +0.04 元（各期利息逐期四舍五入的累积），符合"末期平账 ≤ 1 元"规则。

#### 6.1.3 精度与舍入

| 项 | 规则 |
|----|------|
| 计算精度 | 中间过程使用 `DECIMAL`，月利率保留 8 位小数 |
| 金额落库 | 全部以**分**为单位存整数（`amount_cent`），禁止浮点 |
| 舍入方式 | `ROUND_HALF_UP`（四舍五入），统一在"分"位 |
| 展示精度 | 金额保留 2 位，千分位分隔；利率保留 1 位小数 |
| 客户端 | 不得做任何加减乘除，只做 `formatMoney(cent)` |

### 6.2 IRR（综合年化利率）

#### 6.2.1 定义与口径

- **IRR**：使全部现金流的净现值为 0 的折现率。
- **现金流定义**：
  - `t=0`：`CF0 = +（放款金额 − 一次性服务费）`；无服务费时 `CF0 = +P`
  - `t=1..n`：`CFt = −应还_t`（含本金+利息+不可退费用）
- **年化口径**：`综合年化利率 = r_m × 12`（**单利口径**，其中 `r_m` 为月度 IRR）——与 UI 文案"综合年化利率 X%（单利）"严格一致。
- **展示精度**：保留 1 位小数，`ROUND_HALF_UP`；不做截断。
- **合规校验**：`7.2% ≤ 年化 ≤ 24.0%`，越界则拒绝出单（`RATE_OUT_OF_RANGE`）。

#### 6.2.2 求解方法

```
解方程： Σ(k=0..n) CFk / (1 + r)^k = 0
牛顿迭代：r_{t+1} = r_t − f(r_t)/f'(r_t)
初值 r_0 = 0.02，容差 1e-10，最大迭代 100 次
无解或收敛失败 → 回退二分法，区间 [1e-8, 1.0]
```

**校验**：无服务费时，IRR 应等于定价月利率 `i`（误差 ≤ 1e-6）。用于自动化测试断言。

#### 6.2.3 展示规则

| 位置 | 文案 | 说明 |
|------|------|------|
| 首页 | "年化利率 7.2% 起 · 最高可借 20 万" | 起价表述，需与最低档定价一致 |
| 确认借款页 | "综合年化利率（单利）" + `X%` | 必须带"单利" |
| 合同 | "综合年化利率 X%（单利），采用内部收益率法计算" | 与页面数值一致 |
| 账单/详情 | 同确认页 | — |

**禁用表述**：日息万二、零利息、免息（除明确券后）、低至 X 折、不查征信。

### 6.3 罚息规则

| 项 | 规则 |
|----|------|
| 逾期起算 | 应还款日 23:59:59 前未足额还款，次日 00:00 起计逾期（DPD=1） |
| 逾期本金 | 当期未还本金（不含利息、不含罚息） |
| 日罚息率 | 0.05%/日（年化 18.25%），可按产品参数配置 |
| 罚息公式 | `罚息 = ROUND_HALF_UP(逾期本金 × 0.0005 × DPD, 2)` |
| 上限 1 | 单期罚息 ≤ 逾期本金 × 24% ÷ 365 × DPD（即罚息年化不超过 24%） |
| 上限 2 | 全周期综合成本（利息 + 服务费 + 罚息）年化 ≤ 24%，超出部分自动减免 |
| 计息终止 | 结清日当日不再计罚息（算头不算尾） |
| 示例 | 逾期本金 700 元、DPD=10 → 罚息 = 700 × 0.0005 × 10 = 3.50 元 |
| 冲抵顺序 | 罚息 → 利息 → 本金（可后台配置，变更需超管审批并留痕） |
| 报送 | DPD ≥ 1 记逾期；DPD ≥ 30 上报征信（每月 10 日批量） |

### 6.4 提前结清规则

| 项 | 规则 |
|----|------|
| 违约金 | **0 元**（与首页"提前还款无违约金"文案一致，不得收取） |
| 日利率 | `日利率 = 月利率 / 30`（按 360 天年简化，全产品统一） |
| 计息天数 | 上一还款日（或放款日）至结清日，**算头不算尾**，最少 1 天 |
| 结清金额 | `剩余本金 + 当期应计利息 + 违约金(0) − 未赚利息冲减(0)` |
| 计算公式 | `应计利息 = ROUND_HALF_UP(剩余本金 × 日利率 × 已计提天数, 2)` |
| 上限约束 | 结清金额必须 **≤** 按期还完剩余总额，否则以按期总额为准（防倒挂） |
| 示例 | 前述 12 期示例还款 3 期后（剩余本金 6,106.05），第 4 期已过 10 天：应计利息 = 6,106.05 × 0.0004 × 10 = 24.42，结清应还 = 6,130.47；按期还需 719.80 × 9 = 6,478.20，**节省 347.73 元** |
| 逾期结清 | 先冲罚息，再冲当期利息与本金；结清后 DPD 归零，历史逾期记录不消除 |
| 额度恢复 | 结清成功即释放该笔占用额度，延迟 ≤ 2s |
| 试算有效期 | 10 分钟（`settleId` 绑定金额，超时重算） |

### 6.5 额度与定价公式

#### 6.5.1 授信额度

```
基础额度 B = ROUND_DOWN( 月收入 × 收入倍数 × 风险调节系数 , 100 )
授信额度 L = CLAMP( B , 500 , 200,000 )
首借可借上限 = MIN( L , 50,000 )      ← 首次借款硬上限 5 万
```

| 参数 | 取值 | 来源 |
|------|------|------|
| 收入倍数 | 0.5 / 0.8 / 1.2 / 2.0（按收入等级） | 认证数据（公积金/运营商/代发） |
| 风险调节系数 | 0.6 / 0.8 / 1.0 / 1.3 / 1.6（按风险等级 A~E） | 风控模型输出 |
| 认证加成 | 公积金 +30%（上限 3 万）、运营商 +20%、信用卡账单 +10% | 提额任务 |

**示例**：月收入 12,000、倍数 1.2、风险系数 1.0 → B = 14,400 → 向下取整到百位仍为 14,400 → L = 14,400。

#### 6.5.2 定价

```
综合年化(单利) = CLAMP( 基准年化 × 风险系数 + 期限加点 , 7.2% , 24.0% )
月利率 i = 综合年化 / 12
```

| 风险等级 | 系数 | 基准年化 | 结果区间（12 期） |
|---------|------|---------|-----------------|
| A（优） | 0.67 | 10.8% | 7.2% |
| B | 0.85 | 10.8% | 9.2% |
| C | 1.00 | 10.8% | 10.8% |
| D | 1.25 | 10.8% | 13.5% |
| E（高） | 1.60 | 10.8% | 17.3% |

| 期限 | 加点 | 说明 |
|------|------|------|
| 3 期 | +2.4pp | 短期资金成本高 |
| 6 期 | +1.2pp | — |
| 12 期 | +0pp | 基准 |

**最终示例**：C 级客户、12 期、无券 → 年化 10.8%，月利率 0.9%，8,000 元月供 706.31 元，总利息 475.69 元。
**边界**：任一笔出单前校验 `7.2 ≤ 年化 ≤ 24`，且 `券后年化 ≥ 7.2%`，否则回退到无券方案。

#### 6.5.3 额度占用与释放

| 事件 | 额度变化 |
|------|---------|
| 借款下单成功（未放款） | 冻结 `借款金额`（可用额度 −= 金额） |
| 放款成功 | 冻结转占用（总额度不变，已用 += 金额） |
| 放款失败/关闭 | 释放冻结（可用额度 += 金额），24h 超时自动释放 |
| 还款（部分） | 已用 -= 已还本金，可用 += 已还本金 |
| 提前结清 | 释放剩余本金占用 |
| 逾期 | 不额外占用，但触发额度冻结（F-CRD-07） |

### 6.6 优惠券规则

#### 6.6.1 券类型

| 类型 | 字段 | 作用方式 | 示例 |
|------|------|---------|------|
| 满减券 | `threshold`、`discount` | 直接减免**首期应还**金额 | 满 1,000 减 20 |
| 免息券 | `freePeriods`（1~3） | 减免前 N 期**利息**，重算还款计划 | 免息 1 期 |
| 折扣券 | `rateFactor`（如 0.95） | 对综合年化打折，**重算全期**计划 | 利率 9.5 折 |

#### 6.6.2 叠加与优先级

1. **一单仅可用 1 张券**，不可叠加、不可与活动立减同享（活动立减默认关闭）。
2. 多券可选时，客户端按"预计节省金额"降序排列，默认不选中。
3. 内部优先级（当运营配置冲突时）：`免息券 > 满减券 > 折扣券`。
4. **券后校验**：`券后综合年化 ≥ 7.2%`，否则该券不可用（灰显"不满足使用条件"）。
5. **抵扣上限**：满减券抵扣额 ≤ 首期应还；免息券减免利息 ≤ 对应期利息；折扣券不得使年化低于下限。
6. **不可提现、不可转让、不可找零**；订单取消/放款失败后券自动退回（原有效期不变，已过期则不退）。
7. 同一用户同一券模板最多持有 1 张；券有效期以 `end_at` 为准，精确到 23:59:59。

#### 6.6.3 券后试算示例

8,000 元 / 12 期 / 年化 10.8%（月利率 0.9%）→ 标准月供 706.31，首期应还 706.31，总还款 8,475.69。
使用"满 1,000 减 20"：首期应还 686.31，总还款 8,455.69；券后 IRR 重算后略低于原值（示例约 10.5%，精确值以接口返回为准），页面同步刷新年化与首期金额。

### 6.7 状态机

#### 6.7.1 借款单状态（`loan.status`）

| 状态 | 含义 | 可流转到 | 触发方 |
|------|------|---------|--------|
| `QUOTED` | 已试算未签署 | `SIGNED`、`CLOSED` | 用户/超时 |
| `SIGNED` | 合同已签未提交 | `RISK_REVIEW`、`CLOSED` | 用户/超时 |
| `RISK_REVIEW` | 风控审核中 | `APPROVED`、`REJECTED`、`MANUAL` | 决策引擎 |
| `MANUAL` | 转人工 | `APPROVED`、`REJECTED` | 审批员 |
| `REJECTED` | 风控拒绝 | `CLOSED` | 系统 |
| `APPROVED` | 审核通过待放款 | `DISBURSING` | 系统 |
| `DISBURSING` | 放款中 | `DISBURSED`、`DISBURSE_FAILED` | 资金通道 |
| `DISBURSED` | 放款成功（计息中） | `SETTLED`、`OVERDUE` | 系统 |
| `OVERDUE` | 逾期 | `SETTLED`、`DISBURSED`（补还当期） | 系统/还款 |
| `DISBURSE_FAILED` | 放款失败 | `DISBURSING`（重试）、`CLOSED`（24h 超时） | 用户/系统 |
| `SETTLED` | 已结清 | —（终态） | 还款 |
| `CLOSED` | 已关闭 | —（终态） | 系统/用户 |

**非法流转**一律抛 `INVALID_STATE` 并告警；每次流转写 `loan_status_log`（from/to/operator/trace_id/时间）。

#### 6.7.2 还款单状态（`repay.status`）

`CREATED → PAYING → SUCCESS / FAILED`；`SUCCESS → ALLOCATED`（冲抵完成）；`PAYING` 超 10 分钟由查单任务置 `SUCCESS` 或 `FAILED`。同一 `repayNo` 重复回调幂等。

#### 6.7.3 账单期次状态（`bill.status`）

`UNPAID`（待还）→ `PARTIAL`（部分已还，可选）→ `PAID`（已还）→ `SETTLED_EARLY`（提前结清）；`UNPAID` 逾期后派生 `OVERDUE` 标记（不改变主状态）。

### 6.8 幂等、并发与防重

| 场景 | 机制 |
|------|------|
| 下单 | `Idempotency-Key = SHA1(userId + quoteId + amount + term)`，24h 内同键返回首次结果 |
| 合同签署 | 同一 `quoteId` 仅允许签署一次，重复返回原 `contractNo` |
| 还款 | 同一 `repayNo` 重复请求返回首次结果；同一期次同时只允许 1 笔 `PAYING` 单 |
| 提前结清 | 同一 `loanNo` 只允许 1 个有效 `settleId`；结清中禁止发起还款 |
| 放款重试 | 同一 `loanNo` 同时只允许 1 个重试任务（分布式锁，TTL 5 分钟） |
| 额度变更 | 行级锁 `SELECT ... FOR UPDATE`，避免并发超借 |
| 前端 | 提交按钮点击后立即 `disabled` + loading，请求返回才恢复；页面不做"本地乐观成功" |

### 6.9 时间与日期口径

| 项 | 规则 |
|----|------|
| 时区 | 统一 `Asia/Shanghai`（UTC+8），服务端与客户端展示一致 |
| 还款日 | 取**放款日的对日**；当月无该日则取当月最后一天（如 31 日 → 2 月 28/29 日） |
| 首期还款日 | 放款日 + 1 个自然月（对日规则），不设"首期免息宽限" |
| 计息起点 | 放款成功当日（T+0 起息） |
| 计息方式 | 按日计息、按月还款（账单口径为月） |
| 逾期判定 | 应还日 23:59:59 未足额 → 次日 DPD=1 |
| DPD 计算 | `DPD = 结清日（或今日） − 应还日`，自然日差，同日为 0 |
| 提前结清天数 | 上一还款日至结清日，算头不算尾，最少 1 天 |
| 试算有效期 | quote 10 分钟；settle 10 分钟 |
| 额度有效期 | 授信通过后 30 个自然日 |

## 附录 A 术语表

| 术语 | 含义 |
|------|------|
| 授信 | 风控评估后给予用户的可用借款额度 |
| 首借 | 用户的第一笔成功放款借款 |
| 复借 | 首借之后产生的第 2 笔及以后借款 |

| DPD | Days Past Due，逾期天数 |
| 首逾率 | 首期应还日次日仍未还清的订单占比 |
| Vintage | 按放款月份分组的资产质量追踪方法 |
| 冷静期 | 授信拒绝后不可再次申请的时间窗（30 天） |
| 平账 | 末期还款额按剩余本金重算，吸收前面各期舍入误差 |
| 幂等键 | 保证同一请求重复提交只产生一次业务结果的标识 |
| 冲抵顺序 | 还款金额在各费用项间的分配顺序（罚息→利息→本金） |
